## 第一步：创建 OKX API Key

### 用模拟盘先跑（推荐）

1. 登录 OKX → 右上头像 → **模拟交易**（Demo Trading）
2. 进入模拟盘后 → 头像 → **API** → 创建 API Key
3. 权限只勾 **交易（Trade）**，**不要勾提现**
4. 记下三样：`API Key`、`Secret Key`、`Passphrase`（Passphrase 是你自己设的密码，不是登录密码）

> 模拟盘的 Key 只能在模拟盘用，请求时要带 `x-simulated-trading: 1`（代码已处理，`OKX_DEMO=1` 即开启）

### 切实盘时

同样的流程，但在**主账户**创建，且务必：

| 安全项 | 要求 |
|---|---|
| 权限 | 只勾「交易」，**绝不开提现** |
| IP 白名单 | **绑定东京服务器 IP**（这样 Key 泄露了别人也用不了） |
| 子账户 | 建议用子账户，只放 100 USDT |
| 杠杆 | 在 OKX 上给这几个合约单独设 3x，别用默认 |

## 第二步：部署到东京服务器

```bash
# 1. 建目录
ssh tokyo 'mkdir -p ~/martin-live'
scp -r live/* tokyo:~/martin-live/

# 2. 建环境变量文件（密钥不要进 git）
ssh tokyo 'cat > ~/martin-live/.env <<EOF
OKX_API_KEY=你的key
OKX_SECRET_KEY=你的secret
OKX_PASSPHRASE=你的passphrase
OKX_DEMO=1
EOF
chmod 600 ~/martin-live/.env'
```

**Python 版本**：东京服务器是 3.14，代码只用标准库，无需装依赖。

## 100 USDT 的现实约束

| 项 | 数值 | 影响 |
|---|---|---|
| 单笔风险 | 0.5% = **0.50 USDT** | 亏损体验极小，但**学习信号也很弱** |
| 单笔名义 | 33 USDT | 受粒度影响实际 31–33 |
| 最大持仓 | **6 笔**（200 名义 / 33） | 开不满规格里的 8 笔 |
| 手续费 | taker 0.05%，往返 0.1% = **0.067R** | 相对 E[R]=0.30 侵蚀 22% |
| 月成本预估 | 若 4 笔/周 × 4.3 周 ≈ 17 笔 → 0.57 USDT 手续费 | 约账户 0.6%/月 |
| 达到统计意义 | 30–50 笔 ≈ **6–10 周** | 期间盈亏主要由运气决定 |

**所以：模拟盘阶段看「下单对不对」，实盘阶段看「流程跑不跑得通」，不要看盈亏。**

## 已知缺口（诚实清单）

1. **信号引擎未写** —— 回调买法的日线前置条件（EMA 排列、位置早、距突破日、支撑重合、V 型速度）与 5m 触发都还没实现

3. **状态持久化未写** —— 重启后要能恢复持仓与熔断状态，不能靠内存
4. **信号是简化版** —— 为了先跑通工程，首版可能只实现核心条件（EMA 排列 + 回调到 EMA9 + 5m 突破），完整条件后补，**但必须在配置里标注清楚用了哪几条**
5. **时段结论证据弱** —— `09:00–11:00 UTC` 的结论来自 30 天 × 5 标的，是方向性判断
6. **未做 OKX 与币安的数据差异校准** —— 规格原本基于币安，OKX 的资金费率、最小变动单位都不同
